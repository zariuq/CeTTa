ARCHITECTURE

 ordinary MeTTa match / pat:query / shared continuations
                          |
                owned Space source interface
                  /                     \
        local durable Space          DAS external source
        publication/recovery owner   declared read profile
                  |
        versioned backing roots
        current index; ACT base/segments when qualified

ACT can be native durable backing, not merely an import/export alternative.
The format supplies stored bytes/indexes; the owner supplies commit, recovery
and reader-retention semantics. The current store root API is tied to the
native disk-index format, so using ACT underneath it requires an explicit
adapter or a qualified ACT-base/native-delta layout under one published root.

All adapters must state the semantics they actually provide. DAS can supply
remote storage/query sources and service mechanisms. A future CeTTa provider
could also expose selected local operations to DAS. Neither direction requires
a separate CeTTa query language or an application-specific database engine.

INITIAL ADOPTION DECISION
The local SQLite-replacement milestone does not require a running DAS service
or completion of federation. Apply this intake to avoid duplicating useful
mechanisms, then qualify external-source integration as a separate capability.

Begin with a small read-only external-source prototype and an explicit
capability profile. Reuse DAS's execution/stream/cancel interface where it
meets the lifetime contract; keep ordinary matching and local durable
publication in their existing CeTTa owners. Choose any later writable backend
or provider integration only after semantic and workload qualification.

A remote service lacking captured-view evidence can still be offered as an
explicit best-effort external source. It cannot silently satisfy the stable
captured-read contract used by local KB transactions. Snapshot vectors disclose
which constituent views were read; they do not themselves prove a globally
serializable state across servers.

VERIFIED INTERFACE MAP AT THE PIN

1. src/atomdb/AtomDB.h
   Provides atom/node/link lookup, existence, matching, pattern HandleSets,
   outgoing targets, incoming sets, add/upsert/merge, deletion and counts.
   Bulk add methods include is_transactional=false. The comments explicitly
   qualify merge-enabled adds by a single writer per handle and warn that
   earlier batch items may already be applied on a duplicate-rejection error.
   A transactional flag does not establish every backend's guarantees.
   The inspected public interface has no captured revision/view token argument
   spanning successive queries. This is an interface observation, not a claim
   that every underlying DBMS lacks transactions or snapshots.
   AtomDB get_uid() may be empty; qualify a stable source-domain identity
   rather than assuming this field supplies a unique persistent namespace.

2. src/atomdb/AtomDBAPITypes.h
   HandleList/HandleSet and their iterators are useful candidate surfaces.
   They are not a persistent occurrence-identity contract. AtomDB's default
   add semantics are upsert by atom identity, rather than insertion of a fresh
   independently referenced duplicate occurrence.

3. src/hasher/Hasher.h and expression_hasher.cc
   The current implementation uses MD5-based content handles, including
   recursively derived link handles. Do not substitute the older PoC's hash
   scheme or assume that an independently chosen SHA-256 encoding interoperates.
   Carry a pinned identity/encoding scheme and verify decoded atom structure
   where identity crosses a trust boundary. Keep any stronger canonical digest
   explicitly separate from the DAS-compatible handle.
   Content identity, membership, occurrence identity and authority are distinct.

4. src/atomdb/ProtectedAtomDB.h and auth/AuthorizationManifest.h
   ProtectedAtomDB wraps a backend with Keychain-sensitive access checks and
   schema-based read/write profiles. Translate scoped CeTTa grants explicitly;
   possession of an atom handle is not an authorization grant. Verify endpoint
   authentication and profile/revocation behavior separately from storage APIs.

5. src/agents/query_engine
   QueryElement/QueryNode model asynchronous flow with an explicit finished
   indication. QueryAnswer contains handles, variable assignments, optional
   MeTTa mappings and ranking-related data. The inspected answer representation
   does not attach a captured source revision. Confirm variable and binding
   semantics before pushing a pattern into this engine.

6. src/agents/command_router/http_api
   POST /command-router/executions starts an execution.
   GET /command-router/executions/:id reports status.
   WS /command-router/ws/:id streams buffered events/answers.
   POST /command-router/executions/:id/cancel requests cancellation.
   The code distinguishes queued/running work, terminal results and errors,
   and bounds event storage. Cancellation acceptance says cancel_requested;
   clients must separately observe termination. WebSocket closing alone does
   not establish successful query completion or remote cleanup.

   A WebSocket session starts reading stored events at index0. A reconnecting
   adapter must handle replay by execution/chunk sequence while retaining
   legitimate equal answers from distinct occurrences or derivations.
   Per-execution limits and queue admission are useful server mechanisms, but
   do not by themselves establish an end-to-end credit/backpressure protocol.

7. src/atomdb/morkdb/MorkDB.h and MorkDB.cc
   MorkDB derives from RedisMongoDB and performs pattern queries through a
   MORK client, then constructs local handle/assignment results. This is more
   than a generic file-reader ABI. Audit inherited operations and cross-store
   publication before assuming it supplies one atomic write domain. At this
   pin delete_link reports unsupported and returns false; an adapter must not
   present this as a successful deletion.
   query_for_pattern first obtains a vector of raw expressions. Streaming
   those answers over HTTP does not prove that the server avoided materializing
   the underlying result set before emitting a page. Measure source work and
   retained memory, as well as client-visible chunks.

REQUIRED ADAPTER CONTRACT

- Own the connection, execution ID, row buffers and cursor for their declared
  lifetimes. Closing a cursor requests cancellation and handles the terminal
  acknowledgement/deadline explicitly. Local resource release and confirmed
  remote cleanup are different observations.
- Preserve More/Paused/Complete/Cancelled/Failed/Unknown outcomes. A dropped
  connection, empty poll, attention-limited prefix or accepted cancellation is
  not proof of a complete empty result. Preserve already received partial data
  together with its incompleteness status.
- Tag the backend/identity codec and validate native atom mappings. Preserve
  MeTTa value kinds, open terms, variable sharing and inert stored programs.
  Use shared Space matching when pushdown is not proved equivalent.
- Advertise set-style content views honestly. To qualify as an occurrence bag,
  supply stable occurrence IDs and multiplicity/provenance records; never
  manufacture occurrence IDs from traversal positions or deduplicate by payload.
- Pin a source view for every leg/page of a captured query. If the backend has
  no supported view token, use an explicitly captured local materialization for
  small oracle cases or expose only its weaker external-source profile.
  Whole-KB materialization does not meet the incremental large-KB requirement.
- Include source identity, actual revision evidence and authorization scope in
  cache keys. Unknown freshness and revocation state remain unknown. A content
  handle alone cannot validate mutable membership or permissions.
- Keep query-informed writes behind complete dependency validation. Absent,
  aggregate and recursive/path reads require scopes or conservative validation.
  Unversioned remote reads cannot authorize a native transaction merely because
  all returned rows have stable content handles.
- Preserve attention order as a declared ranking policy, separately from
  completeness and logical identity. Cross-source scores require a common
  scoring context or an explicit conversion. Early stopping yields partial data.
- Charge request budgets for actual source visits, transfer, decode and retained
  resources. Cancelled or disconnected remote work is not automatically free.

FORMAL QUALIFICATION

Mettapedia.Machines.ExternalSpaceAdapter supplies counterexamples/contracts for:
- content-set projection losing occurrence multiplicity;
- reopening one source between join legs manufacturing an answer present in
  neither revision;
- socket closure and cancel-request acceptance being weaker than terminal
  completion or remote-settlement acknowledgement.

The models describe admission obligations; they do not certify DAS's C++ code
or an unimplemented CeTTa adapter. Existing SourceSnapshot, SnapshotBatch and
ToolFailureFeedback results provide additional reusable contracts for captured
inputs, coordinated publication and failure-preserving observations.

SCRIPTED SOURCE CHECKPOINT

test-external-space-source supplies a finite in-process protocol fixture through
the existing SpaceSourceCursorOps interface. It is not a second query engine:
ordinary captured Space cursors perform all matching and joins. Its explicit
profile is CAV1 test mappings, one fixture identity domain, immutable captured
enumeration, stable occurrence memberships, read-only access and no durable
write validation. This mapping is not the DAS MD5-compatible identity codec.

The generic occurrence interface now has PROGRESS: one bounded poll supplied
no row. The ordinary query cursor yields progress, and PeTTa match/pat suspend
with their exact choice retained. Later polls resume that choice, including
first-row suspension and an equation-dispatched match with other alternatives.
Progress does not latch a terminal failure or charge a candidate-row visit.
An unknown source result code becomes sticky INCOMPLETE.

 wait / replay frame -> progress -> resume captured traversal
 row                -> shared matching + occurrence witness
 explicit end       -> complete only for the full captured enumeration
 error / disconnect -> incomplete, preserving an already published prefix

The synchronous native transform realization declines occurrence sources during
pure planning, before opening or polling them. The authored MeTTa definition
remains authoritative and owns ordinary match suspension/error handling; this
fixture checks preflight handoff, not a full remote transform. Existing native agenda selection/discovery
can yield progress; the fixture does not qualify external mutation through
those paths. Native-only fast paths retain their existing admission rules;
older synchronous service consumers refuse unfinished reads as backend errors.

Replay is validated against immutable frame coordinates in the captured test
manifest. A repeated frame is ignored; equal payloads at different occurrences
remain distinct. The fixture exposes namespaced supplied membership identities,
not traversal positions as fact IDs. It compares six patterns/joins against an
ordinary in-memory Space, including repeated variables, distinct variables
binding the same value, shared open variables and inert stored equations.
The source scans complete candidates; remote query pushdown is unqualified.

Data root and execution stream are retained together. Clones/selectors neither
recapture a later publisher nor start a new remote query. Fresh captures can
read a later generation through a new immutable Space handle while old readers
finish the original. An unknown
revision refuses captured-read admission. An explicit content-set profile can
be read as such, but cannot satisfy a requested occurrence-bag profile.
Revocation invalidates a reader; a later regrant cannot revive that old cursor.
These are fixture profile checks, not proof of DAS authorization/revocation.

Cancellation acceptance is not terminal acknowledgement. Closing the last
local cursor requests cancellation; an unacknowledged remote execution remains
an owner obligation. The fixture bounds these obligations and refuses admission
when full. Explicit acknowledgement releases them. Local cursor clones do not
cancel work still held by another reader. Repeated decode/clone/cancel controls
measure retained cursor storage separately from the borrowed finite fixture.

tests/support/external_stream_reference.metta is an executable finite MeTTa
reference for polling, frame coordinates, replay, prefix failures and terminal
states; its test has19checks. Frame coordinates in that reference do not stand
for payload or occurrence identity. The corresponding private Lean model has
nine laws/counterexamples. Neither certifies C, a network peer, immutable remote
execution, authentication or backend snapshots.

The mock is single-threaded and owns an already available finite immutable stream. Its independent
rewind/clone capability is stronger than has been established for a running
DAS execution. It does not demonstrate large remote result retention, streaming
backpressure, reconnection integrity, bounded DAS server memory, an actual DAS
codec or cross-source transactional dependencies. Unversioned external reads
cannot supply a durable-query write context through this fixture.

REMAINING IMPLEMENTATION GATES
1. Select a real backend/codec profile with evidence for the captured-view,
   cursor replay/clone and authorization guarantees actually used. Preserve
   the intake pin or qualify a new one explicitly.
2. Only then run a bounded read-only integration against an explicitly selected
   DAS instance. Keep protocol/backend failures distinguishable from non-match.
3. Evaluate a CeTTa-backed DAS provider and writable integration as separate
   capabilities. Preserve the original single-machine native-KB acceptance gates.

Measure equivalent workloads and semantics before adoption. MORK comparisons
must include the best qualified relevant build, including experimental leapfrog
where it applies; record build options and complete answers. A research report's
capacity estimate is not a measured performance or correctness result.
