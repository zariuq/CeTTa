  For all space d fuel a b, HESmallStep space d fuel a b →
  for all type_ bnd r,
    EvalAtom space d b type_ (stepBindings h) r →
    EvalAtom space d a type_ bnd' r
  (with an explicit binding-transport function `stepBindings` per rule,
   as already realized concretely in mettaCall_absorbs_root_step).

KNOWN TRAPS (each discovered or confirmed this session — do not rediscover):
  T1. M's congruence case is the InterpretTuple/InterpretArgs context lemma:
      a mutual induction over EvalAtom / InterpretExpression /
      InterpretFunction / InterpretArgs / InterpretTuple / MettaCall.
      The naive statement ("evaluation factors through any element") is
      FALSE: argument evaluation order and type-flow (function vs tuple
      path) constrain which elements are evaluated under which expected
      types.  The statement must be validated against at least:
      (i) a function-typed head with per-argument expected types,
      (ii) the tuple path (no function type),
      (iii) an element whose evaluation depends on bindings produced by an
      earlier element (cross-argument type dependency).
  T2. Q is false without side conditions: Empty/Error atoms officially
      pass through with their own constructors, and some quiescent shapes
      (e.g. (case 9 ((3 three)))) officially evaluate to Empty, NOT to
      themselves — Q must exclude exactly the visible-relation quiescents
      that big-step sends to Empty (the no-match sugar shapes).  This is
      why the coarse relation was defined as the VISIBLE relation; Q's
      domain must be characterized accordingly (candidate: quiescent AND
      not a no-match sugar shape AND not Empty/Error — needs a crisp
      predicate, likely "officially-self-evaluating", defined first).
  T3. The fine bindings bookkeeping: EvalAtom recursion threads merged
      bindings; the coarse relation forgets them.  mettaCall_absorbs_*
      handled this with explicit per-rule witness bindings — M must
      generalize that pattern, not quantify naively over bnd.
  T4. Upstream sugar definitions: formalize from the ACTUAL upstream
      stdlib.metta (chain/decons/unify chains), never from an idealized
      recursive-equation rendering — the latter is fake authority.
  T5. fuel: queryEquations/simpleMatch are fuel-indexed; fuel-0 cases are
      vacuous via queryEquations_zero (proven); M should be stated at the
      coarse step's own fuel with constructor-fuel chosen freely on the
      official side (the pattern used in mettaCall_absorbs_equation_match).
  T6 (DISCOVERED while proving Q). InterpretTuple UNWRAPS singletons:
      (x) officially evaluates to x's result, not a 1-tuple; and the
      success-combination SPLICES an expression-valued unwrapped tail.
      Hence self-evaluation is FALSE for singleton wrappers and for
      tuples whose last element is an expression — Q's domain excludes
      them, and M's congruence case must respect the same shapes.
      Whether upstream Rust HE matches this singleton/splice behavior
      deserves an independent probe (possible spec-vs-Lean divergence).
  T7 (DISCOVERED while proving Q). A bare "Error" SYMBOL as any non-head
      element makes a tail-segment Error-SHAPED ((Error ...) expression),
      aborting tuple evaluation — even though the symbol itself is not an
      error atom.  Q's domain excludes bare-"Error" elements; M's
      congruence inversion will meet the same shape conditions.

  T8 (DISCOVERED designing interpretArgs_swap). InterpretArgs treats an
      UNCHANGED Empty/Error argument as "ok, continue to tail"
      (h_head_ok's right disjunct) but a CHANGED Empty/Error result as
      "stop with that result" — so transport across an argument
      replacement fails when either atom is Empty/Error-shaped (the same
      result flips between continue and stop).  interpretArgs_swap
      carries both non-Empty/Error side conditions; M's congruence case
      inherits them (coarse successors can be Error atoms — grounded
      dispatch and equation rhs can produce them — those congruence
      steps are outside the transportable fragment).

  T9 (DISCOVERED during M assembly analysis — IMPORTANT, affects claim
      semantics).  Official evaluation is TYPE-DIRECTED: under expected
      type Atom (and the other type_pass conditions) atoms pass through
      UNEVALUATED, so a coarse step at such a position does not commute
      with official evaluation — the official result is the atom itself,
      and source≠successor means M's same-result conclusion is FALSE
      there.  The C coarse one-step is TYPE-BLIND.  Consequences:
      (a) M is provable on the UNTYPED FRAGMENT (everything
          %Undefined%-typed; type_pass unreachable for expressions under
          %Undefined%, which is exactly chain's expected type);
      (b) on TYPED programs the coarse relation may step where official
          evaluation would not evaluate at all — a REAL potential
          C-vs-official divergence class deserving engine probes with
          type annotations (e.g. (: f (-> Atom Atom)) arguments);
      (c) CLAIM-SEMANTICS QUESTION FOR ZAR: chain/congruence theorems
          will be domain-restricted (untyped fragment).  Does a
          domain-restricted Lean theorem merit the same "rule-sound"
          claim string (with the domain documented in provenance), or a
          distinct level (e.g. "rule-sound-untyped")?  The first two
          flips (grounded/equation/eval) are unconditional, so this is
          a real taxonomy decision, not a formality.

      semantics merges qb into the bindings thread and the TAIL elements

      "same result PAIR" is FALSE across equation steps in element
      position, and the uniform-in-bindings transport hypothesis the
      swap lemmas need cannot come from pair-exact recursion.
