Purpose
-------

This scout fixes the foundation for one concrete cost-accounted rho instance.
The operational instance is the existing CeTTa signature-and-token profile.  Its
spent-signature receipts are interpreted into the effort-object and quantale
models by explicit valuation maps.  The models are not identified by fiat.

The scout changes no CeTTa behavior.  It provides:

1. a source and correspondence audit;
2. a lazy-wrap audit of the C reducer;
3. a concrete Lean syntax, token-cover certificate, and labelled step relation;
4. exact statements for the six next bridge theorems;
5. the decisions that must precede located spaces and Rhometa cost.


Source correction and authority order
=====================================

The local orientation note currently attributes the effort-object/budget model
to the current cost-accounted-rho paper.  The current repository version of
"Cost Accounting for the Reflective Higher-Order Calculus" instead presents
signed terms, signature products, token stacks, located purses, and guarded
COMM.  The explicit EO register and overspend rules are in the older costed
MeTTa operational-semantics source, mops.cost.tex.

The sources therefore have these distinct roles:

* Continued Interactive GSLTs and the Cost Endofunctor, v2:
  wrapped-by-construction sorting, lazy forcing, signature monoid, temporal
  stack, located purse, subject reduction, and the cost construction.
* Cost Accounting for the Reflective Higher-Order Calculus, current version:
  the concrete signed-term/token-stack rho presentation.
* mops.cost.tex:
  effort objects, the fifth `eos` register, cost function `#`, subtraction from
  a budget, and the overspend guard.
* RhometaReduction.lean, CostQuantale section:
  `Payload`, `payloadSup`, and the post-hoc concurrent aggregate `foldCost`.
* Spacetime from Cost:
  the downstream need for firing occurrences, consumed footprints, location,
  enabling, conflict, and trace equivalence.  A scalar total is insufficient
  for this consumer.

This is a source-version mismatch, not a mathematical contradiction.  It does
mean that no bridge may cite the current cost-accounted-rho PDF as the source of
the EO register.


The concrete operational carrier
================================

Let G be the type of ground signing authorities.

  Spatial signature       S(G) = Multiset G
  Temporal token stack    K(G) = List S(G)
  Sequential receipt      R(G) = List S(G)

`S(G)` is the free commutative monoid on G.  It records authority requirements
and retains multiplicity.  `K(G)` and `R(G)` are ordered: a stack exposes only
its head, and a receipt records firing order.

The one operational instance is:

  Cost-rho state  = multiset of signed rho terms and token stacks
  Cost-rho label  = the signature multiset demanded by one COMM
  Cost-rho step   = COMM plus an exact cover of that label by selected heads
  Receipt         = the ordered list of labels along a reduction path

Interpretation is separate from authority:

  value : S(G) -> Delta
  value(0) = 1
  value(a + b) = value(a) * value(b)

For an ordered commutative effort group E, `value` lands first in its positive
cost monoid.  A budget register then uses the group operation to subtract that
positive cost and enforce the overspend guard.  For a commutative quantale
Delta, `value` feeds deterministic step payloads into `foldCost`; nondeterministic
frontiers use ordinary `Payload` sets and their supremum.

Consequently, `rho:cost:sig-mul` is NOT the EO group operation:

* it is a free commutative monoid product;
* it has no inverse;
* repeated authorities are retained;
* CeTTa accepts only nonempty public signatures;
* `rho:cost:sig-unit` is an internal normalization result, not a public
  signature accepted by the validator.

The honest reconciliation is one operational receipt with explicit
interpretations, not one algebra in which signature, money, and lattice join
are declared equal.

C reducer wrap-point audit
==========================

1. Construction / signing

`src/rhocalc_syntax.c` constructs signed terms in `rc_parse_term_atom` after it
has parsed `{ process } signature`.  Stack cells are likewise constructed by
`rc_parse_stack`.  The internal `rhocost_signed` helper is only a constructor
used while preserving an existing signature.  COMM never chooses or mints a
fresh signature.

Verdict: signing occurs at construction/parse time, as required by wrapping by
construction.

2. Strict-core COMM and Rhometa entry

The uncosted path enters deferred MeTTa evaluation in
`rho_compute_comm_continuations`: an output carrying `RHO_EVAL_PAYLOAD` calls
`rho_eval_payload_results`, embeds each result as a name, substitutes it into
the receiver continuation, and lets `rho_emit_comm_results` rebuild each
reaction.

The cost validator `rhocost_check_proc` explicitly rejects `RHO_DROP`,
`RHO_VAL`, and `RHO_EVAL_PAYLOAD`.  `rhocost_collect_steps` therefore has no
Rhometa evaluation entry point.

Verdict: Rhometa evaluation is not silently unpriced; it is outside the current
cost language.

3. Cost COMM discovery

`rhocost_collect_steps` normalizes the input, partitions top-level components
into temporal stacks, separately signed endpoints, and whole signed redexes,
then considers:

* whole redex: one outer signature is the spent label;
* split redex: receiver and sender signatures are combined as a multiset
  product and become the spent label.

Both cases compute the contractum with `rhocost_subst_term` before funding is
enumerated.

Verdict: the runtime implements exactly the two constructors of `CostStep`.

4. Substitution and preservation of wrappers

`rhocost_subst_name` quotes the normalized communicated cost term when it hits
the receive binder.  `rhocost_subst_term` recursively rebuilds existing signed
nodes with the same signature.  Nested receive binders are renamed when needed
to avoid capture.  Existing quoted names are normalized but are not opened by
substitution.

Verdict: substitution carries existing wrappers; it does not sign newly
exposed bare redexes.

5. Funding and forcing

`rhocost_cover_tokens_rec` chooses distinct top-level stack components.  A head
may be chosen only when all of its signature atoms are contained, with
multiplicity, in the remaining demand.  A transition is emitted only when that
demand becomes empty.

`rhocost_emit_step` removes the participant components and each selected head
stack, adds the already-substituted continuation, and adds each selected tail.
Unselected stacks and unrelated components remain.

Verdict: firing consumes exactly one head from each selected stack; it neither
partially consumes a compound head nor exposes a tail early.

6. Normalization versus eager wrapping

`rhocost_normalize_term` traverses, flattens, sorts, and reconstructs the
existing cost syntax.  It preserves every existing signature.  It does not
walk a contractum to attach new wrappers, which is the eager alternative ruled
out by the endofunctor paper.

No semantic eager-wrapping site was found.  The full-term normalization before
frontier enumeration is nevertheless a possible performance hotspot.  It must
be measured separately before claiming the stronger asymptotic benefit of lazy
metering; administrative reconstruction is not itself a fresh-signing step.


Positive and negative witnesses
===============================

Positive: whole wrapper

* A signed parallel receive/send with outer signature `alice * bob`, plus one
  `alice` head and one `bob` head, has a `TokenCover`.
* The step label is the multiset `{alice, bob}`.
* Both selected heads disappear, their empty tails erase structurally, and the
  result is the substituted, already wrapped continuation.

Positive: split endpoints and a compound token

* A receive signed by `alice` and send signed by `bob` on the same channel may
  be funded by one head labelled `alice * bob`.
* The head is consumed atomically; it cannot be split across two firings.

Negative: insufficient multiplicity

* Demand `alice * alice` is not covered by one `alice` head.  Signature product
  is not idempotent.

Negative: buried temporal supply

* A stack `carol : alice : ()` cannot use `alice` to fund the current firing.
  Only `carol` is exposed.

Negative: mismatched channels

* Separately signed endpoints with different channels do not form a split
  `CostStep`, regardless of available tokens.

Negative: Rhometa payload

* `rho:eval-payload` is rejected before the cost frontier is enumerated.  There
  is no default zero price and no synthetic evaluator cost in the Lean syntax.


Bridge vocabulary required before the six theorems
==================================================

The next Lean tranche must add these independent definitions.  In particular,
`runtimeCostFrontier` must be an executable traversal over raw `Pattern` syntax
that mirrors the C partition/cover/rebuild algorithm; it must not be defined by
enumerating proofs of `CostStep`.

  GroundSig                 := String
  encodeSig                 : CostSig GroundSig -> Pattern
  encodeConfig              : CostConfig GroundSig -> Pattern
  decodeConfig?             : Pattern -> Option (CostConfig GroundSig)
  runtimeCostFrontier       : Pattern -> List (Pattern × Pattern)
  CostStructEq              : Pattern -> Pattern -> Prop
  ConfigRuntimeSupported    : CostConfig GroundSig -> Prop
  tokenStacks               : CostConfig GroundSig -> Multiset (CostStack GroundSig)
  WellWrappedRuntime        : Pattern -> Prop
  CostPath                  : CostConfig G -> List (CostSig G) -> CostConfig G -> Type
  CostPath.depth            : CostPath source receipt target -> Nat
  SignatureValuation G D    : Type
  deterministicPayload      : SignatureValuation G D -> CostSig G -> Payload Unit D
  CostPath.totalCost        : SignatureValuation G D -> CostPath source receipt target -> D

`CostStructEq p q` is equality after an independently defined structural
normalizer: AC flattening/sorting for both rho parallel and cost parallel,
signature-product flattening/sorting with multiplicity, and erasure of the
empty cost stack at top level.

The C/Lean trust boundary remains explicit.  Proving the theorems below relates
the declarative `CostStep` to an independently executable Lean model of the C
algorithm.  Universal correspondence with compiled C additionally requires a
checked extraction or a systematic cross-language conformance harness; the
existing fixture TSV supplies examples, not that universal theorem.


The six bridge theorem statements
=================================

1. costStep_sound_runtime

  theorem costStep_sound_runtime
      (hsource : ConfigRuntimeSupported source)
      (hstep : CostStep source spent target) :
      (encodeSig spent, encodeConfig target) ∈
        runtimeCostFrontier (encodeConfig source)

Every declarative, runtime-supported cost step is emitted by the independent
runtime-frontier model with the same spent label and target.

2. costStep_complete_runtime_up_to_struct

  theorem costStep_complete_runtime_up_to_struct
      (hsource : ConfigRuntimeSupported source)
      (hfrontier :
        (rawSpent, rawTarget) ∈ runtimeCostFrontier (encodeConfig source)) :
      ∃ spent target,
        rawSpent = encodeSig spent ∧
        CostStep source spent target ∧
        CostStructEq rawTarget (encodeConfig target)

Every emitted runtime transition has a declarative witness; only the declared
structural quotient may differ syntactically.

3. wellWrapped_preserved

  theorem wellWrapped_preserved
      (hwrapped : WellWrappedRuntime rawSource)
      (hfrontier :
        (rawSpent, rawTarget) ∈ runtimeCostFrontier rawSource) :
      WellWrappedRuntime rawTarget

This theorem is deliberately stated on raw syntax.  Stating it only after
decoding into the intrinsically wrapped `CostTerm` grammar would make the
claim vacuous.

4. no_free_redex

  theorem no_free_redex
      (hsource : ConfigRuntimeSupported source)
      (hunfunded :
        ∀ residual, ¬ TokenCover spent (tokenStacks source) residual) :
      ¬ ∃ target, CostStep source spent target

The useful immediate corollary is that a runtime-supported configuration with
no token stacks has no `CostStep`.  A syntactic receive/send pair alone is not
a cost transition.

5. spent_depth_eq_steps

  theorem spent_depth_eq_steps
      (path : CostPath source receipt target) :
      receipt.length = path.depth

There is exactly one spent signature record per forced COMM.  Structural
normalization contributes neither a receipt element nor a step.

6. trace_account_eq_totalCost

  theorem trace_account_eq_totalCost
      [CommMonoid Delta] [CompleteLattice Delta] [IsQuantale Delta]
      (valuation : SignatureValuation GroundSig Delta)
      (path : CostPath source receipt target) :
      foldCost (receipt.map (deterministicPayload valuation)) =
        path.totalCost valuation

The left side passes the exported ordered receipt through the existing quantale
aggregate.  The right side accumulates the independently labelled steps of the
path.  Their equality is the conservation theorem.  For an EO interpretation,
a later ordered-group corollary must additionally show that accepted execution
changes the budget by exactly this total and never crosses the overspend guard.


Collection and concurrency decision
===================================

Superseded decision: the primary receipt is a located measured pomset of firing
occurrences.  Direct arcs are generated by consumption and retain multiplicity.
The runtime list is only a linearizing presentation of that object.  There is
no schedule quotient, no deduplication, and no separately axiomatized
independence relation.  See the active causal-receipt design.


Rhometa and spaces-as-channels decision
======================================

Rhometa pricing is deferred by design.  It is gated on the spaces-as-channels
architecture in the rho rebuild brief, specifically its open questions about:

* the channel/space ownership invariant;
* ownership transfer or safe aliasing under channel mobility;
* shared versus cloned registry and space state under threaded execution;
* payload/result representation without a reducer fork;
* localized evaluation failure;
* the formal frame for mechanized ownership and COMM-time evaluation.

The current sibling-isolated transactional evaluator is an emulation, not the
target parallel space semantics.  Pricing its snapshot and overlay mechanics
would make an implementation artifact part of the language cost.

The dependency order is therefore:

1. pure-rho cost instance and its six bridge theorems;
2. spaces-as-channels with explicit ownership, mobility, isolation, and true
   parallel execution semantics;
3. Rhometa-plus-cost, where payload evaluation enters as priced ownership and
   computation events.

The join theorem must say that trace-equivalent permutations of independent
firings have the same account.  It must not equate conflicting histories.


Decisions requiring confirmation or later design
=================================================

D1. Rhometa evaluation price -- RESOLVED FOR THIS LANE

Deferred until spaces-as-channels exists.  No evaluator price is selected and
no evaluator constructor is added now.

D2. Receipt collection dial -- RESOLVED

Use the located measured causal pomset as primary.  The runtime ordered log
retains cause pointers and merely linearizes it.

D3. Signature valuation -- FOUNDATION IMPLEMENTED

Additive and multiplicative valuations are constructed as universal folds of
the raw signature multiset.  Concrete economic weights remain policy inputs.

D4. Located purse representation -- SUPERSEDED BY PURE-CLOSURE TRANCHE

Every event carries opaque funding-location identifiers.  The scout's ambient
placeholder has since been replaced by nominally located purses and exact
per-head funding contributions.  Ownership and mobility remain gated on
spaces-as-channels.

D5. Firing receipt richness -- RESOLVED

The dedicated traced machine emits stable occurrence IDs, consumption causes,
funding contributions, and raw spend before state-frontier deduplication.  The
ordinary step interface remains compatible.

D6. Normalization cost -- REQUIRES MEASUREMENT, NOT A SEMANTIC CHANGE

Measure full-term normalization separately from wrapping.  If it dominates,
optimize canonical representation or incremental indexing while preserving the
same frontier and all correctness gates.
