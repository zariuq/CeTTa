MISSION
-------
Upgrade rhometta from "read-only snapshot + commuting fold" to its settled final
form, with the Lean theory catching up to (and then certifying) the C runtime:

    Rhometta semantics =
        choice  (⊔)  over compatible COMM matchings        [contention]
      + parallel(⊗)  commutative fold inside one matching  [existing theory]
      + sequence(;)  closure across rounds                 [chaining]
      + transactional payload labels (result, local delta, owned exports, cost)

This is a richer semantics of the SAME operational core (rho orchestrates
rendezvous; MeTTa computes payloads at COMM time). It is not a new kernel.

DECISION LOG (ratified 2026-06-11 — do not reopen)
--------------------------------------------------
(a) Match(P) base = ALL compatible matchings (not maximal-only, not
    scheduler-realizable-only). Consequences: singleton matchings are matchings,
    so the exact one-redex reducer embeds as the finest refinement; every
    concrete scheduler (canonical, rotating, threaded) is a refinement of the
    same base relation, to be tested/proven as such.
(b) Owned exports are FIRST-CLASS in the Lean outcome object
    (result × delta × exports), with a reification-embedding theorem connecting
    it to the C runtime's residual-carrying form (owned results returned as
    values in the residual). The C runtime keeps reifying; the theory keeps Ω
    explicit and proves the reification faithful.
(c) Layering split (who owns which branching):
      - Match(P) / compatibility / rounds / runs   → rho/rhocalc semantics
      - PayloadOutcomes(e)                          → MeTTa/HE semantics
        (HE spec, hyperon-experimental/docs/metta.md:556: matching two atoms
        without custom grounded matchers yields exactly one binding set, so
        payload branching enters only via space multi-hits, multiple equations,
        superpose, custom matchers)
      - scheduler / replay policy                   → runtime implementation,
        never the calculus ("relations are public; schedulers are runtime
        choices")
(d) Cost/quantale work re-attaches only AFTER the structural layers exist
    (otherwise cost theorems about the commuting subcase get misused as if they
    governed contention and chaining).

B2. First-class Ω outcome object + reification embedding (Decision (b))
    - PayloadOutcome (R Δ Ω) := R × Δ × Multiset Ω; generalize
      Payload R Δ := Set (R × Δ) to PayloadΩ R Δ Ω := Set (PayloadOutcome R Δ Ω);
      the existing theory is the Ω := Empty (or PUnit) instance — re-expressed,
      not re-proven.
    - foldOutcomesΩ: same recursive product; exports accumulate by Multiset
      union (commutative — the perm theorem extends verbatim).
    - Reification: reifyΩ : PayloadOutcome R Δ Ω → (R × Ω-tagged-residual) × Δ —
      the abstract form of the C runtime returning owned results as values in
      the residual. Theorems:
        reifyΩ_injective      : reification is injective (no information loss);
        reifyΩ_fold_commutes  : fold-then-reify = reify-then-fold.
    - Distinguishing example (the no-go-3 content): two payload sets with equal
      result/delta projections but different Ω, distinguishable after reify —
      so process-only outcomes WITHOUT reified exports are too coarse, and
      reification is exactly what restores faithfulness.

B3. Event layer (concrete operational object, not full event-structure machinery)
    - EventSkeleton: consumed output occurrence, consumed input occurrence,
      channel, payload (a PayloadΩ). Occurrences as indices into the frontier
      (the .collection list up to par_perm), matching the engine's frontier
      representation.
    - Compatible e e' : Prop — distinct consumed occurrences (no shared linear
      send or recv), disjoint export identities. Keep it a structure of two
      named conditions so later refinements (footprint conflicts) extend it.
      Scope note: Compatible is the MODEL-level relation and is deliberately
      weaker than the engine's macro side conditions (quiet continuations,
      copy-stable results, no alternative pairing). In the model, payload
      non-interference is structural (payload outcome sets are fixed data on
      skeletons; frozen base + isolated scratch are baked into the type), so
      bare Compatible carries the abstract theorems. The engine-side conditions
      are NOT extra hypotheses for the same theorems — they are what makes a
      live C macro step BE an instance of an abstract round at all. They enter
      exactly once, as explicit hypotheses of macro_collapse_corollary (B6),
      and are tracked in the CORRESPONDENCE TABLE below.
    - Matching := { M : Finset EventSkeleton // pairwise Compatible }.
    - MatchOf P := all matchings whose events are enabled in P (Decision (a):
      ALL compatible matchings, including ∅ and singletons).

B4. Round layer
    - roundOutcomes P := ⋃ (M ∈ MatchOf P), foldOutcomesΩ (payloads M).
    - singleton_step_embeds : every exact one-redex step outcome appears as the
      {e} matching's contribution (the exact reducer is the finest refinement).
    - independent_unique_matching_collapses_to_fold : if the enabled events are
      pairwise Compatible (no contention), then the full-frontier fold's
      outcome set is a member contribution of roundOutcomes P:
      foldOutcomesΩ (enabled events) ⊆ roundOutcomes P. Exactly two membership
      statements in B4 — the singleton embedding above and this one. NO
      "sub-matching outcomes extend to the full fold" claim here: that is not a
      defined relation on (result, delta, exports) triples, and the true
      statement ("partial rounds complete in later rounds, so sub-rounds add
      nothing to quiescents") is a closure fact that lives in B6, where
      sequential composition makes it well-formed. This pair is the theorem A4
      needs.

B5. No-go theorems (concrete witnesses, mirroring Engine.lean:682 and :711)
    - contention_requires_choice : for the one-send/two-receivers process,
      roundOutcomes has two distinct outcomes consuming the same send, and NO
      function of the form "commutative fold over all enabled events" (i.e. a
      single foldOutcomesΩ application to the whole enabled set) equals it.
      Statement quantifies over the fold-shaped semantics, witnessed by the
      concrete process.
    - chaining_not_single_round : for send c a | recv c x. send d x | recv d y. Q,
      the quiescent outcome containing Q[a/y] is in the two-round closure but
      in NO single-round denotation determined by the initial frontier.

B6. Run layer + the crown (TWO theorems, deliberately split)
    - runOutcomes (fuel) C := fuel-indexed sequential closure of roundOutcomes;
      quiescents = members with no enabled COMM.
    - round_granularity_independence (abstract crown, bare Compatible): the
      quiescent set of the singleton-only closure equals the quiescent set of
      the all-matchings closure — bigger compatible rounds add no quiescent
      outcomes and lose none. (⊆ by singleton_step_embeds + induction; ⊇ by
      serializing one compatible matching into singleton steps via
      foldOutcomesΩ_perm.) Provable at bare Compatible BECAUSE the model bakes
      payload non-interference in structurally; this theorem is a statement
      about the model, and citing it as an engine guarantee without the
      corollary below is the overclaim this document exists to prevent.
      Known proof obligation: serialization must rename owned-export
      identities (splitting a round into singleton steps re-derives freshness;
      expect an alpha-renaming lemma on Ω, stated up to export-identity
      bijection).
    - macro_collapse_corollary (engine crown): under the EXPLICIT hypotheses
      mirroring the C macro's side conditions — unique maximal matching (no
      alternative pairing), quiet continuations, copy-stable results,
      transactional payload isolation — a macro-fired round is an instance of
      an abstract round, hence by the abstract crown semantically invisible.
      Every hypothesis here must appear as a row of the CORRESPONDENCE TABLE;
      a hypothesis the proof never uses is a conservatism finding (report it —
      A4 candidate), a needed assumption with no C-side enforcing check is a
      soundness alarm (stop and report immediately). This pair is the Lean
      justification for both the existing macro and A4.
