Linking, naming and publication

Linking makes the dependency graph available transitively, deduplicated by actual module identity. Naming publishes the explicitly imported module's exports into this importer's lexicon. Being linked through a different module does not satisfy a later request for those lexical names. Preserve token selection priority and whole-token behavior through the existing registration mechanisms.

Initialization, export and invocation are separate events. An initializer is not rerun merely to expose already initialized exports to another importer. Export hooks may run for a new importer according to the identified reference/profile contract.

Atomic publication protects importer links and tokens. A failed module may retain private state that escaped callbacks legitimately own; already completed external I/O cannot be erased. Successfully initialized children remain usable under the established profile rules. Restore nested module/session context after both normal and failing exits, and use the existing ownership and close mechanisms for retained callbacks.

Default he/extended remember failures for the established importer/module/source identity and allow the documented source-change retry. he-compat uses the identified reference contract, including the agreed repaired import cases. The restart draft's blanket sentence that every retry is fresh does not override the default profile policy.

The module reference contract was updated with Zar's approval on 2026-10-09: he-compat follows the identified fixed HE fork on module cases, including fresh attempts after failed initialization and removal of children belonging to a failed parent. Atomic failed-export publication and direct-import naming after a transitive link remain part of that contract. Keep the pinned observations as records of the defects alongside the fixed-fork comparisons. This does not authorize automatically adopting unrelated or later fork changes.

Dependency views and observations

Own-before-imported priority applies where the language requires it. A diamond shares a module once, but two equal stored atom occurrences remain two occurrences. Listing, counting and mutation keep their own-only contracts; get-atoms must not be turned into an imported-space listing just because matching or type lookup reads dependencies. module-space-no-deps is the explicit own-storage view.

Compare answer bags by values and multiplicity. Lists, inner atom structure, token choice, precedence and effects keep required order. Retained storage is a lifetime guarantee; current observations additionally depend on the governing revisions. Reuse the baseline's reader and ownership services instead of reopening a completed observation or retaining a stale cache result.

Scope retained for the restart

The eight operations and their module behavior are this project. Preserve normal/light C HE availability, Python module support, PeTTa, Prime, Rho and existing permitted profile extensions, including targeted include where provided.

Keep the baseline's kernel built-in representation and call route for this goal. The full kernel operation-value conversion, P11 authority completion, reader/regex/Unicode/number changes, native-call or compiler optimization, general module algebra and full C/ABI/C11 verification are deferred projects. Their existing settled principles remain retained: HE authority comes from acquired values and defining contexts; PeTTa keeps its own name-based interpretation; native library names are lexical, with system/fs/json additions belonging to extended profiles. Deferral is not a claim that those obligations are already complete.

The default repeated-include change proposed by Opus was marked as a recommendation, not an approved settlement. Preserve the existing documented profile behavior until that choice is resolved from the concrete evidence and high-level intent. This rewrite does not introduce a new include policy.

No arbitrary default search limits. Existing optional user-requested limits remain optional. Reuse existing dependencies and ownership services; the module project does not add a Rust dependency, regex library, build-time download or ownership framework.
