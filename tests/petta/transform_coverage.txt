PeTTa and transform: what is covered, and by which test
=========================================================

Two directions.

  transform -> PeTTa   transform written with PeTTa's own match, add-atom and
                       remove-atom:  lib/petta/lib_transform_specs.metta (the
                       specification), lib/petta/lib_transform_swi.metta, and
                       the calculus's own rule form in lib/petta/lib_step_rules.metta
  PeTTa -> transform   PeTTa's forms written with transform:
                       lib/petta/lib_petta_by_transform.metta, and whole programs
                       rewritten by lib/petta/transform_only.metta

Gates.

  make test-petta-transform                 native, lib_transform_swi, lib_transform_specs on CeTTa
  make test-transform-swi-differential      the same programs on SWI-PeTTa as well, four ways
  make test-petta-by-transform[-swi]        the laws of tests/petta/petta_by_transform.metta
  make test-petta-transform-only[-swi]      the programs of tests/petta/transform_only/
  make test-petta-transform-only-corpus     a directory of example programs, with its list of known exceptions
  make test-petta-transform-only-corpus-full   the same with binding, branching and choice rewritten too
  make test-petta-transform-only-corpus-swi    the same directory through the round trip on SWI-PeTTa
  make test-petta-machine[-swi]             the checks of tests/petta/petta_machine.metta and seeded expressions
  make test-petta-step-rules[-swi]          the checks of tests/petta/step_rules.metta
  make test-petta-step-rules-reference      random firings against the C reference step

A row names the form and the test that holds it, or says why there is none.

2. transform's surface in plain PeTTa (lib_transform_specs.metta)
-----------------------------------------------------------------

  conjunct or rule                         test
  read, take, absent, unique, collect,     tests/petta/transform_*.metta; the seeded classes
  let, all, once, (tf:as P A)              ground, guard, spaces, route of test-transform-swi-differential
  proposals at the call, one branch each   the same; class "consumer" (a caller acting between answers)
  a kernel let that chooses                each answer is a branch of its own and fires the answer it stands
                                           for; class "choice"; laws kernel-let-choice-*.  Its expression runs
                                           at the call and again at each firing (law
                                           kernel-let-runs-at-the-call-and-at-the-firing)
  validation by multiplicity               the negative control of test-transform-swi-differential
  function and space destinations          class route; class spaces
  a value that is no atom (a partial       class values
  application) in a pattern or template

  a row that holds a variable: what a      tests/petta/transform_open_rows.metta, compared four ways
  rule makes from it keeps the variable    (plain-made, computed-made, apart-made): also when the rule
  where the row had it                     computes a value from the row in a let conjunct.  The
                                           PeTTa-written libraries collect a branch's let answers,
                                           and a collected answer is a copy; each is kept beside the
                                           instance of the expression that gave it and met with the
                                           expression again.
  a let conjunct whose expression binds    the PeTTa-written libraries keep the binding, as match
  a variable (a function run backwards)    does with the same let in its body; the native firing
                                           keeps the answer and drops the binding (reported to the
                                           native lane; not in the compared classes)

  limits of this representation
  stored atoms that hold variables         class open (reported): remove-atom removes everything its
                                           argument unifies with, so a take of one occurrence is exact
                                           only where occurrences can be told apart by their atoms.
                                           lib_step_rules keeps an identity with each occurrence and
                                           takes exactly one.
  a destination named by a symbol          read as a function; lib_petta_by_transform's pt:add-atom
                                           stores under such a name through the caller

                             value, an if two heads True and False, a case one head for each row with
                             every row but the last cutting, a superpose one head for each element; a

                             thunk with quoted arguments.  A value reaches a generated function as an
                             argument and is never evaluated again.  Fixtures held_values,
                             streamed_case, nested_control (tests/petta/transform_only); of the 150
                             example programs 134 pass that way (518 of 553 tests), 136 with those
                             forms left to the host (523).
  a part entered after a     a generated function is entered when it is reached.  A body that defines
  definition                 a function and then mentions it as data has the mention in a part entered
                             after the definition, where it is a call; as written the mention stays
                             data for that invocation.  Fixture defined_then_mentioned, listed in
                             tests/support/petta_transform_only_full_known.txt; examples
                             callquoteevalreduce and definition_order, one test each.
  the evaluator itself       lib/petta/petta_machine.metta: PeTTa's evaluation as a table of transform
                             rules (pm:rule KEY SOURCES TEMPLATE).  The machine's state is one stored
                             atom; a let binds by a take, clause choice is a read of the clause row, a
                             choice point is a row of its own, backtracking takes the newest.  once
                             keeps the depth it was entered at and its first answer takes the choice
                             points above it; collapse keeps its answers in a row of its own, which
                             outlives backtracking; case offers its value to the rows in order; cut
                             takes the choice points made since the clause was entered.  Checks of
                             tests/petta/petta_machine.metta and seeded expressions answer as the
                             host, in order (make test-petta-machine, test-petta-machine-swi).  It
                             covers literals, if (with or without an else), let, let*, chain,
                             superpose and hyperpose (of a written list, or of a variable), empty,
                             quote, eval, data, calls of the program's equations, patterns with
                             PeTTa's list view (cons H T) in heads, lets and case rows, applied
                             values, lambdas, partial and over-application of the program's names,
                             declarations that hold an argument or the answer as written, equations
                             added or removed while the program runs, foldall, maplist, prog1, the
                             stream forms, add-atom, remove-atom, match, once, collapse, case (with
                             or without an Empty row), progn and cut.  A head that is no equation of
                             the program is the host's: the machine evaluates its arguments and the
                             host applies it to the values (a request between rules; every answer an
                             alternative; data comes back as it went).  A value may hold a variable:
                             what a later let, a match or an application by the host binds reaches
                             the value made earlier and the code after it, for that alternative
                             alone (each answer of a request is kept beside the instance of the
                             request that gave it, and the rule that takes the answer meets that
                             instance with the request the state holds).  A call of a function of
                             the program written as a let's pattern runs toward the let's value, as
                             on the hosts: a constructor in a body meets the value before its items
                             run, so the search of a function run backwards ends where the value
                             does.  The machine knows as constructors the symbols the program takes
                             apart in an equation's head; the host's metatype does not tell (it is
                             Symbol for a library's native operations too).  A pattern is read as an
                             expression, as on the hosts: a call of a function of the program or of
                             an operation of the host in an equation's head, a let's pattern or a
                             case's row says that what stands there is an answer of the call, which
                             runs toward that value (in a case's row: before the rows are offered);
                             an operation of the host toward a value is handed the value with the
                             application, so (append ($x) $y) toward (1 2 3) has one answer; in a
                             let's pattern (quote P) stands for P and a form is evaluated.  A case
                             row with a list view is taken only if the view opens.  Declared types
                             (conformance spec 4.7): each declaration that describes a call is an
                             alternative with arguments of its own, held as written (Atom),
                             evaluated (%Undefined%, _) or evaluated and checked (any other type, a
                             type variable too; what a type asks is fixed by the declaration as
                             written), the result checked, an equation's body answered as written
                             when the declaration with its number of inputs answers Atom; whether a
                             value has a type is asked of the host, whose relation get-type a
                             program can extend.  map-atom, filter-atom and foldl-atom with a
                             variable and a body run their body on the host.  Definition timing
                             (conformance spec 3, P-DEF-4): a name's equations are kept as written;
                             when a name gains its first equation or loses its last, the stored
                             bodies that mention it are compiled again, and a body that is running
                             keeps the term it holds.  A space written as an expression is
                             evaluated first.  Errors: an operation a rule computes that raises,
                             raises on the machine; the nearest catch answers the error as a value
                             and the choices made inside it are dropped; an operation with no
                             answer is no answer; an error a request to the host raises is raised
                             on the machine.  A written application of a host operation is asked
                             of the host once, as code in which each value is given by a variable
                             of its own: a value that is code or a quotation is handed over as it
                             is, and what the operation raises is raised.  A head that came as a
                             value is applied with reduce, as the hosts apply it, where an
                             operation that raises has no answer.  call and reduce make their
                             application when it is reached (a head with equations by then is
                             called, also in a running body); forall; a lambda applied to fewer or
                             more values than it has parameters.  A goal of the host's Prolog,
                             (translatePredicate (G A1 ... An)) (conformance spec, P-PL-2): the
                             arguments are evaluated on the machine, the host calls the goal with
                             the values as they are, and each way it holds is an alternative with
                             what it bound.  Not covered: a
                             declaration given after the equations that call its name; an argument
                             of type Atom of a call made through a value; the checks of a partial
                             application before it is completed; a constraint of the host's solver
                             across a request; a form in a variable-headed let pattern, which the
                             hosts evaluate before the pattern meets the value; a lambda
                             handed to an operation of the host.  How much of

                             measured by tests/support/check_petta_machine_corpus.py (nothing is
                             required); the programs are given to the machine as text.
